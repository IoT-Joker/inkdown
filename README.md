# Inkdown

一个模仿 [Typora](https://typora.io/) 的桌面 Markdown 编辑器，以 [marktext](https://github.com/marktext/marktext) 的编辑器内核 **muya**（`@muyajs/core`）为基础构建。

- **实时渲染（所见即所得）**：边写边渲染，光标所在段落显示 Markdown 源码，离开后立即呈现排版效果
- **应用外壳**：文件树、多标签、大纲、状态栏、查找替换、偏好设置、多主题
- **内核能力**：CommonMark + GFM、表格、任务列表、KaTeX 数学公式、Mermaid/PlantUML/Vega 图表、Prism 代码高亮、脚注、YAML 前言、上下标

## 与 marktext 的关系

marktext 已重构为 monorepo：`packages/muya`（纯 JS/DOM 的编辑器内核）与 `packages/desktop`（Electron 外壳）。

Inkdown 把 marktext 的 **muya 内核源码**（develop 分支）以 workspace 包的形式内联到 `packages/muya`，
直接作为编辑器内核复用；外壳、交互与 Typora 式功能全部自行实现。这样做的原因：

- npm 上发布的 `@muyajs/core@0.2.0` 是**精简快照**，只暴露 18 个方法，
  缺少 `updateParagraph`、`format`、`createTable`、`insertImage`、`getCursorOffset`、
  `setFocusMode`、`revealElement` 等 Typora 式交互必需的 API；
- develop 分支的完整源码提供约 60 个公共方法，覆盖段落转换、行内格式、表格、
  光标换算、专注模式、大纲跳转等全部能力；
- 内联源码后由 Vite 直接编译 TypeScript，无需额外构建步骤。

同时避开了 desktop 包中 `keytar` / `native-keymap` / `@vscode/ripgrep`
等原生依赖带来的构建负担。

```
src/
  main/        Electron 主进程：窗口、IPC、菜单、端到端自检、截图
  preload/     上下文隔离桥接（window.inkdown）
  renderer/    Vue 3 界面
    src/components/   编辑器宿主、标签栏、侧边栏、状态栏、查找栏、偏好设置
    src/composables/  命令总线、文件操作、导出
    src/editor/       muya 内核封装与插件注册
    src/store/        全局响应式状态与设置持久化
    src/assets/styles 应用样式与主题变量
packages/muya/       内联的 marktext 编辑器内核源码
examples/demo.md     功能演示文档
```

## 功能

| 分类 | 能力 |
| --- | --- |
| 编辑 | 所见即所得实时渲染、源码模式、撤销/重做、自动配对括号与 Markdown 语法 |
| 排版 | 标题 1-6、引用、代码块、数学公式块、表格、分隔线、YAML 前言 |
| 行内 | 加粗、斜体、下划线、删除线、行内代码、高亮、行内公式、超链接、图片 |
| 视图 | 大纲、文件树、专注模式、打字机模式、5 套主题、缩放 |
| 文件 | 新建/打开/保存/另存为、打开文件夹、多标签、自动保存、外部改动检测、会话恢复 |
| 工具 | 查找与替换（正则/大小写/全词）、字数统计、导出 HTML/PDF |
| 界面 | **中英文切换**（含原生菜单与对话框） |

### 界面语言

偏好设置 → 外观 → **界面语言**，可选简体中文 / English。

切换后立即生效，并且：

- 应用内所有文案（菜单栏、标签栏、侧边栏、状态栏、查找栏、偏好设置、提示条）随之切换
- **原生菜单栏与系统对话框**也会重建为对应语言
- 编辑器内部的浮动工具（表格菜单、图片工具等）由 muya 内核语言包负责，同样跟随切换
- 选择结果持久化，下次启动沿用（首次启动按系统语言自动选择）

### 菜单栏

窗口顶部自绘菜单栏（文件 / 编辑 / 段落 / 格式 / 视图），与原生菜单共用同一套命令，
行为一致。原生菜单栏已隐藏，但快捷键仍由系统级菜单提供。

菜单包含一些 marktext 式的实用项：

| 菜单项 | 说明 |
| --- | --- |
| 文件 → 最近打开 | 列出最近打开的文件，可一键重开或清除记录 |
| 编辑 → 插入当前时间 | 在光标处插入 `YYYY-MM-DD HH:MM:SS` |
| 编辑 → 复制段落 | 复制当前段落 |
| 编辑 → 在下方插入段落 | 在当前段落后插入新段落 |
| 编辑 → 删除段落 | 删除当前段落 |
| 编辑 → 换行符 | 切换 LF（Unix）/ CRLF（Windows），**会按所选行尾写盘** |

### 查找与替换

按 `Ctrl+F` 打开查找、`Ctrl+H` 打开替换。查找栏左侧有放大镜图标标识输入框，
计数显示为 **「当前序号 / 总数」**（如 `2 / 5`），一眼看出当前位置与总量。

- 支持区分大小写、全词匹配、正则表达式
- 当前匹配与其余匹配用不同样式区分
- **切换文件再回来，搜索结果会自动恢复**：编辑器内核在切换文档时会重置搜索状态，
  Inkdown 会记住关键词并在文档重建后自动重搜，回车继续可用

### 全库搜索

`Ctrl+Shift+F`（或菜单 **编辑 → 在文件夹中查找**）在已打开的文件夹内递归搜索所有
Markdown 文件。结果按文件分组、显示行号与高亮命中，点击即打开该文件并跳到对应行。

实现是**纯 Node 零依赖**（`src/main/folderSearch.ts`），不引入 ripgrep 之类的原生依赖——
后者更快，但会显著增加打包体积与构建复杂度。取舍：

- 递归时跳过隐藏目录、`node_modules`、`dist` 等
- 单文件超过 2 MB 跳过；每文件最多 20 处命中，总数上限 500（超出会提示截断）
- 只搜 Markdown 扩展名，与文件树范围一致

### 命令面板

`Ctrl+Shift+P`（或菜单 **视图 → 命令面板**）列出命令中心里的全部命令，
按名称模糊过滤（空格分隔的多词为「与」匹配），↑↓ 选择、Enter 执行、Esc 关闭。

### 分栏预览

视图有**三态**：所见即所得 → 分栏预览 → 纯源码，点状态栏的视图按钮或按 `Ctrl+/` 循环切换。

**分栏预览把阅读与编辑分开：左边实时显示渲染效果，右边是等宽字体的源码编辑器。**

- 左侧是渲染结果，随输入即时更新（打字时左侧跟着变）
- 右侧是 Markdown 源码，可直接编辑
- 两者共用同一份内容：在右侧改的每个字符都会同步到左侧预览与标签内容

分栏右上角有一个可拖动的 3D 悬浮球（位置会自动记住）。悬停展开 Markdown 分类环；
把鼠标移到有下级的分类上，外圈继续展开具体动作，点击即可在光标处插入标题、列表、
代码块、表格、提示块、折叠块、公式或当前时间等常用结构。

预览区使用同步渲染器，**不渲染 Mermaid/Vega 等图表**（那需要异步运行时，会拖慢输入响应）；
需要完整图表时用导出功能。

### 拖拽

| 位置 | 行为 |
| --- | --- |
| 标签栏 | 拖动标签调整顺序；拖到目标左半插前、右半插后 |
| 文件树 | 拖到目录中部移入该目录，拖到上/下缘调整同级顺序 |

文件树拖拽禁止把目录拖进自身子孙；目标已存在同名文件时给出提示；
移动后会同步已打开标签的路径，避免保存时写回旧位置。

### 关于与帮助

菜单栏最右侧的 **帮助** 菜单提供：

| 菜单项 | 说明 |
| --- | --- |
| 键盘快捷键 | 打开快捷键速查面板（按功能分组，41 条） |
| 项目主页 / 反馈问题 | 在系统浏览器打开对应页面 |
| 关于 Inkdown | 应用图标、版本、标语、构建来源、许可与运行时版本（Electron / Chromium / Node），可一键复制版本信息便于反馈 |

### 应用图标

图标是 **文档 + 文字行 + 插入光标** 的造型：折角纸张是最通用的文本编辑器识别形状，
内部三条长短不一的文字行暗示标题与正文层级，右下角的琥珀色光标点出「正在编辑」。
蓝紫渐变底保持品牌调性。

源码为矢量图 [build/icon.svg](build/icon.svg)，由脚本生成各尺寸位图：

```bash
pnpm icons      # 生成 build/icon-*.png 与 build/icon.ico
```

| 产物 | 用途 |
| --- | --- |
| `build/icon.ico` | Windows 打包（8 个尺寸：16–256） |
| `build/icon.png` | 窗口图标、macOS / Linux 打包 |
| `build/icon-{16..512}.png` | 各尺寸位图，供需要单独尺寸的场景 |

窗口图标在开发时即生效；打包配置已指向这些产物。

### 打包成安装程序

```bash
pnpm package        # Windows 安装程序（NSIS）+ 免安装目录
pnpm package:dir    # 只出免安装目录，速度快
```

产物在 `release/`：`Inkdown Setup <版本>.exe`（安装程序）与 `win-unpacked/`（免安装版）。

`scripts/package.js` 处理了三个本机特有的障碍：

1. **Node 与 pnpm 不在 PATH** —— electron-builder 需要**直接执行** `pnpm` 来收集依赖树，
   而本机 Node 是内置运行时、pnpm 是 `.mjs` 文件。脚本在项目外生成 `node.cmd` / `pnpm.cmd`
   垫片并临时加入 PATH。
2. **GitHub 直连不通** —— Electron 与打包工具链的二进制改从 npmmirror 取。
3. **pnpm 输出混入提示行** —— electron-builder 会解析 `pnpm list --json` 的 stdout，
   任何非 JSON 的提示都会让它报 `No JSON content found in output`。
   已在 `.npmrc` 固定 store 目录并静音输出。

打包产物体积：安装程序约 124 MB，免安装目录约 499 MB（Electron 运行时占大头）。

### 文件树与拖入

- **文件树只显示 Markdown 文档**（`.md` / `.markdown` / `.mdown` / `.mkd` / `.mkdn` / `.mdx` / `.txt`）。
  目录始终保留用于导航，图片、脚本、配置等文件不会混入。
- **拖入 `.md` 文件即可打开**：拖拽时显示投放提示层，支持一次拖入多个；
  非 Markdown 文件会被忽略并给出提示。

### 会话恢复

关闭软件再打开时，**上次打开的标签页会自动恢复**（含活动标签）。
已被删除或移动的文件会跳过，未命名文档不参与恢复。

### 未保存提示

- 标签栏与窗口标题在文件名后显示 `*` 表示有未保存改动
- 关闭标签或退出时提示「保存 / 不保存 / 取消」，取消则中止关闭
- 应用自身的保存**不会**触发「外部修改」提示；只有真实的外部改动才会
  （以非阻塞提示条呈现，不打断写作）

## 开发

需要 Node.js 20+ 与 pnpm。

```bash
pnpm install
pnpm dev        # 开发模式（热更新）
pnpm build      # 生产构建
pnpm typecheck  # 主进程 + 渲染层类型检查
pnpm verify     # 构建 + 端到端自检 + 真实文件工作流测试
pnpm shots      # 生成界面截图到 screenshots/
```

### 如何启动

**方式一：双击** `启动 Inkdown.bat`（Windows 最省事）

**方式二：命令行**

```bash
pnpm build      # 首次需先构建
pnpm start       # 或：node scripts/start.js
```

**方式三：直接运行 Electron**（无需 Node 在 PATH）

```bash
node_modules\electron\dist\electron.exe .
```

启动脚本 `scripts/start.js` 会自动处理两个环境问题：
`node` 不在 PATH 时改用内置运行时；剔除宿主的 `ELECTRON_RUN_AS_NODE=1`。

启动后按 `Ctrl+O` 打开 [examples/demo.md](examples/demo.md) 体验全部功能。

**2. 真实文件工作流测试**（`pnpm filetest`）——验证完整链路：

打开文件 → 编辑内容 → 保存到磁盘（并回读校验）→ 导出 HTML 并落盘
→ 导出 PDF（校验 `%PDF-` 头部与体积）→ 文件树只显示 Markdown → 会话记录。

**3. 会话恢复测试**（`pnpm sessiontest`）——分两次启动真实进程：

第一次打开两个文件并记录会话；第二次全新启动，校验自动恢复的标签与活动标签
（要求恰好 2 个，防止测试数据污染悄悄通过）。

**3. 像素采样**（`node scripts/sample-pixels.py <png>`）——客观核对截图配色，
避免仅凭肉眼判断主题是否生效。

**4. PDF 内容核对**：主进程支持把导出的 PDF 渲染成图片
（`INKDOWN_RENDER_PDF=<pdf>`），用于确认导出内容不含应用界面。

## 已知环境问题

部分环境（如宿主设置了 `ELECTRON_RUN_AS_NODE=1`）会让 Electron 退化为纯 Node 模式，
启动时报 `Cannot read properties of undefined (reading 'whenReady')`。
三个测试脚本已自动剔除该变量；本地 `pnpm dev` 若遇到同样报错，请先清除它。
