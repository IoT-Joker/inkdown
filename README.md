# Inkdown

一个面向技术文档的桌面 Markdown 阅读与编辑工具：阅读模式、源码编辑与导出预览。

- **阅读模式**：渲染完整文档，支持选字、复制、链接跳转，避免误输入；可使用单页或相邻双页阅读。需要修改时切换到源码或源码预览。
- **应用外壳**：文件树、多标签、大纲、状态栏、查找替换、偏好设置、多主题
- **编辑能力**：CommonMark + GFM、表格、任务列表、KaTeX 数学公式、Mermaid/PlantUML/Vega 图表、Prism 代码高亮、脚注、YAML 前言、上下标
- **导出**：HTML、PDF、Word（.docx）；先预览再保存，记住纸张、方向、边距、字号和页码设置。
- **源码预览**：左侧编辑源码、右侧实时渲染，光标所在块用虚线框标出并自动跟随

## 关于编辑器内核

编辑器内核以 workspace 包的形式内联在 `packages/muya`，由 Vite 直接编译 TypeScript，
无需额外构建步骤。选择内联源码而非 npm 依赖的原因：

- npm 上发布的精简版只暴露 18 个方法，缺少 `updateParagraph`、`format`、`createTable`、
  `insertImage`、`getCursorOffset`、`setFocusMode`、`revealElement` 等交互必需的 API；
- 完整源码提供约 60 个公共方法，覆盖段落转换、行内格式、表格、光标换算、
  专注模式、大纲跳转等全部能力。

这样也避开了 `keytar` / `native-keymap` / `@vscode/ripgrep` 等原生依赖带来的构建负担。

```
src/
  main/        Electron 主进程：窗口、IPC、菜单、端到端自检、截图
  preload/     上下文隔离桥接（window.inkdown）
  renderer/    Vue 3 界面
    src/components/   编辑器宿主、标签栏、侧边栏、状态栏、查找栏、偏好设置
    src/composables/  命令总线、文件操作、导出
    src/editor/       muya 内核封装与插件注册
    src/store/        全局响应式状态与设置持久化
    src/assets/styles 应用样式与主题变量
packages/muya/       编辑器内核（内联源码）
examples/demo.md     功能演示文档
```

### 界面语言

偏好设置 → 外观 → **界面语言**，可选简体中文 / English。

切换后立即生效，并且：

- 应用内所有文案（菜单栏、标签栏、侧边栏、状态栏、查找栏、偏好设置、提示条）随之切换
- **原生菜单栏与系统对话框**也会重建为对应语言
- 编辑器内部的浮动工具（表格菜单、图片工具等）由 muya 内核语言包负责，同样跟随切换
- 选择结果持久化，下次启动沿用（首次启动按系统语言自动选择）

### 菜单栏

窗口顶部自绘菜单栏（文件 / 编辑 / 段落 / 格式 / 视图），与原生菜单共用同一套命令，
行为一致。原生菜单栏已隐藏，但快捷键仍由系统级菜单提供。

菜单还包含一些实用项：

| 菜单项 | 说明 |
| --- | --- |
| 文件 → 最近打开 | 列出最近打开的文件，可一键重开或清除记录 |
| 编辑 → 插入当前时间 | 在光标处插入 `YYYY-MM-DD HH:MM:SS` |
| 编辑 → 复制段落 | 复制当前段落 |
| 编辑 → 在下方插入段落 | 在当前段落后插入新段落 |
| 编辑 → 删除段落 | 删除当前段落 |
| 编辑 → 换行符 | 切换 LF（Unix）/ CRLF（Windows），**会按所选行尾写盘** |

### 查找与替换

按 `Ctrl+F` 打开查找、`Ctrl+H` 打开替换。查找栏左侧有放大镜图标标识输入框，
计数显示为 **「当前序号 / 总数」**（如 `2 / 5`），一眼看出当前位置与总量。

- 支持区分大小写、全词匹配、正则表达式
- 当前匹配与其余匹配用不同样式区分
- **结果列表**：点计数旁的 ▾ 展开全部命中，每条显示「行号:列号」与命中上下文，
  点击任意一条直接跳到该处；比逐个按「下一处」更适合通览
- **切换文件再回来，搜索结果会自动恢复**：编辑器内核在切换文档时会重置搜索状态，
  Inkdown 会记住关键词并在文档重建后自动重搜，回车继续可用

结果列表里的行号按**整篇文档**计算。内核返回的是块内偏移，直接用它会让每个段落
都显示第 1 行；实现上把块文本定位回全文再换算行号，因此显示的是真实行。

### 大纲折叠

侧栏「大纲」页签里，含子标题的条目前有折叠箭头，点一下收起其下所有子标题；
顶部还有 **全部收起 / 全部展开** 两个按钮，长文档按章节浏览更方便。

折叠状态按标签记录，切换文档不会串到别的文档。

### 全库搜索

`Ctrl+Shift+F`（或菜单 **编辑 → 在文件夹中查找**）在已打开的文件夹内递归搜索所有
Markdown 文件。结果按文件分组、显示行号与高亮命中，点击即打开该文件并跳到对应行。

实现是**纯 Node 零依赖**（`src/main/folderSearch.ts`），不引入 ripgrep 之类的原生依赖——
后者更快，但会显著增加打包体积与构建复杂度。取舍：

- 递归时跳过隐藏目录、`node_modules`、`dist` 等
- 单文件超过 2 MB 跳过；每文件最多 20 处命中，总数上限 500（超出会提示截断）
- 只搜 Markdown 扩展名，与文件树范围一致

### 命令面板

`Ctrl+Shift+P`（或菜单 **视图 → 命令面板**）列出命令中心里的全部命令，
按名称模糊过滤（空格分隔的多词为「与」匹配），↑↓ 选择、Enter 执行、Esc 关闭。

### 源码预览

视图有**三态**：阅读模式 → 源码预览 → 纯源码，点状态栏的视图按钮或按 `Ctrl+/` 循环切换。阅读模式的单页和双页均允许选择复制，支持大纲章节高亮及跳转返回。

**源码预览把编辑与阅读分开：左边是等宽字体的 Markdown 源码，右边实时显示渲染效果。**

- 左侧是 Markdown 源码，可直接编辑
- 右侧是渲染结果，随输入更新，并按设置跟随源码位置
- 两者共用同一份文档；预览支持提示块、公式和异步图表渲染

分栏右上角有一个可拖动的 3D 悬浮球（位置会自动记住）。悬停展开 Markdown 分类环；
把鼠标移到有下级的分类上，外圈继续展开具体动作，点击即可在光标处插入标题、列表、
代码块、表格、提示块、折叠块、公式或当前时间等常用结构。

预览区先渲染正文，再异步处理 Mermaid / PlantUML / Vega 等图表，未变化的图表会复用。PlantUML 使用设置中配置的服务，离线时可能无法生成。

### 导出预览与预设

文件 → 导出 HTML / PDF / Word 会先打开导出预览。可选 A4、A5、Letter、纵向或横向，设置四边页边距、正文字号及页码。内置标准、紧凑、舒适阅读预设，也会记住上次自定义参数。

右侧展示实际 PDF 打印预览；Word 使用相同参数，但最终分页由 Word 排版决定。HTML 在浏览器中为连续文档，预览展示其打印参考，页码以 PDF / Word 为准。

预览就绪后即可直接导出，不需要额外勾选确认。取消导出不会写入文件。PDF / Word 保留标题书签，Word 的复杂图表按图片保留。

### 打印

文件 → 打印（`Ctrl+P`）直接调起系统打印对话框，由用户在对话框里选打印机、纸张与份数。

打印不经过导出预览：系统对话框本身就负责页面设置，多一层预览反而绕。但生成的 HTML 与导出一致（同一套图表渲染与 CSS），所以打印出来的效果与导出的 PDF 相符。取消打印不会报错。

### 性能特征（实测）

用 `pnpm perf` 可复现以下数据（打包版、本机）：

| 场景 | 耗时 |
| --- | --- |
| 冷启动（进程 → 可编辑） | 平均 ~960 ms |
| 载入 200 段落（17 KB） | ~94 ms |
| 载入 800 段落（69 KB） | ~557 ms |
| 载入 2000 段落（174 KB） | ~2960 ms |
| 连续输入（200 / 800 段落） | p50 5 / 9 ms |
| 主题切换（200 / 800 段落） | 14 / 50 ms |
| 全库搜索（200 / 1000 文件） | 49 / 125 ms |
| 滚动 800 段落 | p50 17.6 ms（~57 fps），**掉帧率 0%** |
| 反复替换 600 段落文档 8 次 | 堆 26 MB → 26 MB（**无泄漏**） |
| 内存 | JS 堆 ~26 MB，主进程 ~125 MB |

结论：

- **滚动、输入、内存、搜索都很健康**，没有可感知问题。
- **大文档载入是唯一严重的性能瓶颈**，且随文档增大明显超线性：
  200 段 94 ms → 800 段 557 ms → 2000 段 2960 ms。
  实测 4000 段（349 KB）需要约 12 秒，属于不可用。
- 瓶颈归属已定位：**纯内核 `setContent` 与应用层封装耗时一致**
  （800 段落：561 ms vs 554 ms），说明统计/大纲/列布局都不是原因，
  问题在内核渲染管线。另一个对照：2000 段纯正文（无标题）仅 593 ms，
  带标题则 2988 ms，说明成本主要来自标题相关的结构与样式。
- 主题切换的开销几乎全在浏览器样式重算（实测纯 CSS 切换占 50/50 ms）。
  曾尝试 `content-visibility: auto`，只降 9% 且影响光标与搜索定位，未采用。

### 自动更新

应用支持自动更新，更新源为 GitHub Releases。

| 方式 | 行为 |
| --- | --- |
| 启动时自动检查 | 默认开启，可在 **偏好设置 → 更新** 关闭。发现新版本会询问是否下载，不会擅自占用带宽 |
| 帮助 → 检查更新 | 手动检查，一定会给出结果：发现新版本 / 已是最新 / 失败原因 |
| 下载完成后 | 提示「立即重启」安装；若选「稍后」，退出应用时会自动安装 |

几个实现上的取舍：

- **先问再下**：`autoDownload` 关闭，避免在用户不知情时下载上百 MB 的安装包
- **禁用清单缓存**：更新器默认会缓存 `latest.yml`，实测发布新版本后本机仍读到旧版本号
  （要手动删 `%LOCALAPPDATA%/inkdown-updater` 才能刷新），因此请求时带上
  `Cache-Control: no-cache`，保证能及时看到新版本
- **错误信息归类**：不会把原始 HTTP 响应（含响应头与 cookie）抛给用户，
  而是按 404 / 网络失败 / 认证失败归成一句可读的说明

**已知限制**：未配置代码签名证书，Windows 安装新版时仍会弹 SmartScreen 警告，
这是系统行为，自动更新无法绕过。

### 交互性能

滚动与悬停必须跟手。下面几条是实测数据支撑的做法，改动前请先跑对应脚本。

**图表渲染不得打断滚动。** Mermaid 是同步计算，单次实测阻塞主线程 50–57ms；
若在滚动中触发，滚轮与 hover 事件会排在其后，表现为「滚轮转了一圈、页面过一会儿才动」。
因此图表渲染等**滚动静止 160ms 后**才开始，并去掉 `requestIdleCallback` 的
`timeout` 强制触发 —— 空闲不足时宁可等下一帧，也不为「按时渲染」卡住主线程。

实测对比（滚动 6 秒 + 悬停 3 秒）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| p99 帧间隔 | 42.1ms | 17.1ms |
| 最长帧 | 67.5ms | 31.5ms |
| >33ms 的帧 | 8 | 0 |
| 长任务 | 2 个 / 107ms | 0 个 / 0ms |

**相关脚本**

| 脚本 | 用途 |
| --- | --- |
| `node scripts/jank-profile.js` | 抓长任务与帧抖动，含 DOM 读取来源归因 |
| `node scripts/latency-diagnose.js` | 诊断 GPU 状态、滚动/悬停耗时、大面积阴影 |

### 打包成安装程序

```bash
pnpm package        # Windows 安装程序（NSIS）+ 免安装目录
pnpm package:dir    # 只出免安装目录，速度快
```

产物在 `release/`：`Inkdown Setup <版本>.exe`（安装程序）与 `win-unpacked/`（免安装版）。

`scripts/package.js` 处理了三个本机特有的障碍：

1. **Node 与 pnpm 不在 PATH** —— electron-builder 需要**直接执行** `pnpm` 来收集依赖树，
   而本机 Node 是内置运行时、pnpm 是 `.mjs` 文件。脚本在项目外生成 `node.cmd` / `pnpm.cmd`
   垫片并临时加入 PATH。
2. **GitHub 直连不通** —— Electron 与打包工具链的二进制改从 npmmirror 取。
3. **pnpm 输出混入提示行** —— electron-builder 会解析 `pnpm list --json` 的 stdout，
   任何非 JSON 的提示都会让它报 `No JSON content found in output`。
   已在 `.npmrc` 固定 store 目录并静音输出。

打包产物体积：**安装程序约 80 MB，免安装目录约 281 MB**。

### 体积优化

Electron 应用天然偏大（运行时本身就有约 200 MB），但初始打包曾达到
安装包 127 MB / 目录 522 MB，其中约 200 MB 是**纯冗余**：

| 组成 | 优化前 | 优化后 | 做法 |
| --- | --- | --- | --- |
| `app.asar` 内 node_modules | 253.5 MB | 51.3 MB | 排除渲染层已 bundle 的依赖 |
| Electron 语言包 | 40.3 MB（55 个） | 1.4 MB（3 个） | `electronLanguages` 只留中英 |
| 安装包 | 127.2 MB | **80.2 MB** | |

**关键原理**：渲染层的依赖（mermaid、vega、katex、prismjs、muui 等）已由 Vite
**完整 bundle 进 `out/renderer`**，运行期不会再从 `node_modules` 读取。
而主进程只有 `docx` 与 `electron-updater` 被 externalize（bundle 里是 `require('docx')`），
这两个及其依赖才必须随包携带。删掉前者不损失任何功能——
打包版自检里 Mermaid 图表依然正常渲染。

**踩过的坑**：排除规则**绝不能用 `lodash*` 这类宽通配**。
`electron-updater` 依赖 `lodash.isequal` / `lodash.escaperegexp`，
被误删后打包版启动即崩（`Cannot find module 'lodash.isequal'`），
而开发环境完全正常——这类问题只有跑打包版才暴露。

为此新增两个校验（`pnpm verify:package`）：

- `scripts/verify-package.js` —— 静态校验：解析 asar，从主进程 bundle 提取
  externalize 的裸包，递归确认这些包及其依赖闭包都在，并抽查关键文件
- `scripts/verify-packaged.js` —— 动态校验：直接运行打包产物并跑完整自检，
  输出里出现 `Cannot find module` 会单独列出

建议每次改动打包配置后都跑一次 `pnpm verify:package`。

### 文件树与拖入

- **文件树只显示 Markdown 文档**（`.md` / `.markdown` / `.mdown` / `.mkd` / `.mkdn` / `.mdx` / `.txt`）。
  目录始终保留用于导航，图片、脚本、配置等文件不会混入。
- **拖入 `.md` 文件即可打开**：拖拽时显示投放提示层，支持一次拖入多个；
  非 Markdown 文件会被忽略并给出提示。

### 会话恢复

关闭软件再打开时，**上次打开的标签页会自动恢复**（含活动标签）。
已被删除或移动的文件会跳过，未命名文档不参与恢复。

### 未保存提示

- 标签栏与窗口标题在文件名后显示 `*` 表示有未保存改动
- 关闭标签或退出时提示「保存 / 不保存 / 取消」，取消则中止关闭
- 应用自身的保存**不会**触发「外部修改」提示；只有真实的外部改动才会
  （以非阻塞提示条呈现，不打断写作）

## 开发

需要 Node.js 20+ 与 pnpm。

```bash
pnpm install
pnpm dev        # 开发模式（热更新）
pnpm build      # 生产构建
pnpm typecheck  # 主进程 + 渲染层类型检查
pnpm verify     # 构建 + 端到端自检 + 真实文件工作流测试
pnpm shots      # 生成界面截图到 screenshots/
```

### 如何启动

**方式一：双击** `启动 Inkdown.bat`（Windows 最省事）

**方式二：命令行**

```bash
pnpm build      # 首次需先构建
pnpm start       # 或：node scripts/start.js
```

**方式三：直接运行 Electron**（无需 Node 在 PATH）

```bash
node_modules\electron\dist\electron.exe .
```

启动脚本 `scripts/start.js` 会自动处理两个环境问题：
`node` 不在 PATH 时改用内置运行时；剔除宿主的 `ELECTRON_RUN_AS_NODE=1`。

启动后按 `Ctrl+O` 打开 [examples/demo.md](examples/demo.md) 体验全部功能。

## 已知环境问题

### 稳定性检查与异常日志

本轮修复保存期间输入误标已保存、重复打开覆盖修改、源码命令操作隐藏编辑器、
重命名后保存到旧路径，以及同名图片覆盖。保存采用临时文件完整写入后替换，
遇到外部修改会提示重新加载或另存为；关闭标签会释放旧文件监听。

未保存文档每隔约 750 ms 保存最近的恢复快照。异常退出后重启自动恢复；
磁盘文件已改变时把草稿单独打开，避免自动覆盖。正常确认放弃修改并退出后清除快照。
偏好设置的外观分组可调整圆盘字号、不透明度和动画。

`pnpm regression` 运行保存竞争、图片重名和源码编辑回归；`pnpm recoverytest`
验证真实重启恢复与外部文件冲突。`pnpm filetest` / `pnpm sessiontest` 也使用
独立临时目录，不会结束正在使用的应用进程。

构建后运行 `node scripts/stability-test.js`，检查表格重复点击、拖拽取消、
失效表格菜单、深色菜单对比度和分栏内容同步。`--smoke` 运行完整编辑器自检，
`--shots` 生成界面截图。每次使用独立的临时用户目录，不会结束正在使用的应用进程。

应用异常记录在用户数据目录的 `logs/diagnostics.log`；Windows 默认位于
`%APPDATA%/inkdown/logs/diagnostics.log`。日志包含渲染进程退出原因、子进程异常、
未捕获错误和窗口无响应事件，单份最多约 2 MB，保留一份轮转备份。
原生崩溃转储由 Electron 保存在本机，不上传到服务器。

部分环境（如宿主设置了 `ELECTRON_RUN_AS_NODE=1`）会让 Electron 退化为纯 Node 模式，
启动时报 `Cannot read properties of undefined (reading 'whenReady')`。
三个测试脚本已自动剔除该变量；本地 `pnpm dev` 若遇到同样报错，请先清除它。
